## 6. 판정과 권고

**판정(사전 봉인 규칙 적용)**: 지표 2 = 1 > 0 → 보류 대안 개봉 논의 개시. 본 이슈는 여기서 종료, 개봉은 별도 이슈.

**권고안(개봉 이슈의 출발점, 책 근거)** — 책에서 pivot 은 의견이 아니라 구조에서 기계적으로 정해지는 값이다(오닐: 손잡이 고점 + 소폭, 손잡이 없으면 컵 왼쪽 고점, 더블바텀은 가운데 봉우리 / 미너비니: 마지막 수축 구간 고점). 사람이 안 흔들리는 이유는 지난주를 기억해서가 아니라 같은 구조에서 같은 계산이 나오기 때문. 직전 판독 첨부(anchoring)는 #1 결정대로 계속 기각.

1. **방향 한정 래칫(1순위, 작음)**: 같은 베이스(same·near)에서 새 pivot < 직전 활성 pivot 이면 직전 값을 트리거 기준으로 유지, 높으면 새 값. 근거 = 같은 베이스에서 pivot 은 내려오지 않으며 내려온 pivot 으로 사는 것은 "베이스 안 매수". 숫자 임계가 없어(방향만) 허용폭 근거 문제를 피한다. 해제 조건 = 직전 행 ignore 또는 different(활성 기준선 단절, `_pivot_continuity` 와 동일 의미론). 비용 = 직전 pivot 이 과대 판독이면 매수가 늦어짐(책의 안전한 쪽 실패, extended 가드 기존).
2. **결정론 pivot 유도(구조적, 큼)**: LLM 은 패턴·베이스 경계만 답하고 pivot 은 코드가 저장 주가에서 책 정의대로 계산(#21 의 entry 파라미터 결정론화와 같은 방향). 전제 = 손잡이 구간 등 경계 필드(현재 스키마 미확인, 추정)·프롬프트 변경(governance 4-6)·백테스트 재현성 영향.
3. 베이스 고유 ID 추적: 1·2 가 base_start_date 키로 같은 효과 — 비권장.

본 판독의 숫자(돌파 1·promotion 반사실 1·왕복 79)는 개봉 이슈에서 1안의 기대 효과 상한으로 쓴다: 1안은 지표 2 의 1건과 promotion 1건을 모두 막았을 것이다(두 건 다 옛 pivot 기준 미발화).
