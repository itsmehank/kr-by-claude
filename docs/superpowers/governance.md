## 원칙 1: 제거 판정 (2026-09-02, #151 승인에서 확정)

게이트·상수·파생값을 판정에서 **제거**할 때의 판정 기준(1-1)과 기록 처리(1-2).

### 1-1. 제거 판정 4조건 (전문가 확정, #151 에서 코드로 재확인)

**네 개 다 충족할 때만 지운다. 하나라도 아니면 안 지운다.**

- (a) 제약 추가형·필수 매개변수 아님 — 제거 후 파이프라인 정상.
  (#151: suite 1339p)
- (b) 커버리지 손실 없음 — 같은 책 요구를 담당하는 다른 장치가 남아 있음.
  (#151: 베이스 구간은 A `wide_and_loose` §5.2 담당 — D4 불변)
- (c) book-mandated 신호와 방향 충돌. (#151: corr +0.578)
- (d) 미정의 계산 없음 — 산출·소비 동시 제거.

### 1-2. 기록 보존 — 파생값 vs 원시 관측

- **저장 OHLC 등에서 재계산 가능한 파생값**은 판정에서 제거할 때 기록도 함께 제거할 수
  있다 — 정보 손실이 없기 때문. (예: spread_ratio_vs_avg = high−low 및 그 이동평균)
- **재계산 불가능한 원시 관측**(LLM 응답·reasoning, 당시 시장 상태 스냅샷 등)은 판정에서
  제외하더라도 **기록은 보존**한다.

단서:
- (i) **"재계산 가능"은 그 파생값의 산출 정의가 문서에 보존된 경우에만 성립**한다.
  정의가 소실되면 동명 필드를 다른 정의로 재계산하게 되어 과거 저장본과 비교가
  불가능해진다 — **파생값 기록 제거 시 정의 원문 보존이 선행 조건**.
  (#151 의 A1 — plans/2026-09-02 문서의 정의 원문 보존 — 이 절차의 최초 적용 사례)
- (ii) 1-2 는 제거를 **허용**하는 규약이지 **요구**하는 규약이 아니다. "제거 가능"을
  "제거 필요"로 해석하지 말 것.

## 원칙 2: 권한 분리 (2026-09-02 #151 에서 확정, 2026-09-03 질의 규약 통합)

> 각 주체는 자기 권한 밖의 판단을 하지 않는다.
> 리포의 사실 기반 트리거는 방법론 판정보다 우선한다.
> CC는 책 해석·source tag 부여·책에 없는 임계 신설·결측 시
> 동작을 스스로 정하지 않고 질의한다.

### 2-1. 리포 자동 규칙이 우선

- 리포 규칙의 **사실 기준 트리거**(예: threshold-change-checklist 의 "thresholds.py 또는
  소비처를 건드렸나")는 세션/외부 문서의 **방법론 판정("이건 임계 변경이 아니다" 류)으로
  우회하지 않는다**. 실질 판정이 기계적 트리거를 면제하지 않는다.
- 발단: #151 외부 지시문이 "checklist 대상 아님"으로 판정했으나 상수 삭제는 사실 트리거에
  해당 — 의존성 맵을 작성했고 이 우선순위를 규약으로 명문화.

### 2-2. CC가 물어봐야 하는 경우 / 알아서 해도 되는 경우

**질의가 필요한 경우 — 예시이지 목록이 아님**:
책에 없는 수치를 정해야 할 때 / 책 문구가 둘로 읽힐 때 / 저자 간 서술이 충돌할 때 /
source tag 를 붙여야 할 때 / 결측·null 일 때 통과인지 차단인지 정해야 할 때 /
지시에 없는 조건을 추가해야 할 것 같을 때.
판단이 애매하면 질의한다. **추측으로 채우고 사후 보고하지 않는다.**

**단독 결정 가능**: 명명·배치·테스트 구조·리팩터링·로깅 형식 등
임계값과 분기 조건에 영향이 없는 범위.

### 2-3. 물어볼 때 양식

```
[Q-n]
- 결정 사항: (한 문장)
- 선택지와 동작 차이: A/B/C 각각에서 어떤 종목이 어떻게
  다르게 판정되는지 구체적으로
- 확인한 코드 사실:
- CC 추정: (있으면 "추정" 라벨 필수. 없으면 "없음")
```

여러 건은 모아서 한 번에. 해당 부분만 중단하고 독립 부분은 진행 가능.
