# 프로젝트 governance 규약

> 개별 이슈/체크리스트를 관통하는 일반 규약. 발단 사례를 각 항목에 병기한다.

## G1. 기록 보존 규약 — 파생값 vs 원시 관측 (2026-09-02, #151 승인에서 확정)

- **저장 OHLC 등에서 재계산 가능한 파생값**은 판정에서 제거할 때 기록도 함께 제거할 수
  있다 — 정보 손실이 없기 때문. (예: spread_ratio_vs_avg = high−low 및 그 이동평균)
- **재계산 불가능한 원시 관측**(LLM 응답·reasoning, 당시 시장 상태 스냅샷 등)은 판정에서
  제외하더라도 **기록은 보존**한다.

단서:
- (i) **"재계산 가능"은 그 파생값의 산출 정의가 문서에 보존된 경우에만 성립**한다.
  정의가 소실되면 동명 필드를 다른 정의로 재계산하게 되어 과거 저장본과 비교가
  불가능해진다 — **파생값 기록 제거 시 정의 원문 보존이 선행 조건**.
  (#151 의 A1 — plans/2026-09-02 문서의 정의 원문 보존 — 이 절차의 최초 적용 사례)
- (ii) G1 은 제거를 **허용**하는 규약이지 **요구**하는 규약이 아니다. "제거 가능"을
  "제거 필요"로 해석하지 말 것.

## G2. 사실 트리거 우선 규약 (2026-09-02, #151 에서 확정)

- 리포 규칙의 **사실 기준 트리거**(예: threshold-change-checklist 의 "thresholds.py 또는
  소비처를 건드렸나")는 세션/외부 문서의 **방법론 판정("이건 임계 변경이 아니다" 류)으로
  우회하지 않는다**. 실질 판정이 기계적 트리거를 면제하지 않는다.
- 발단: #151 외부 지시문이 "checklist 대상 아님"으로 판정했으나 상수 삭제는 사실 트리거에
  해당 — 의존성 맵을 작성했고 이 우선순위를 규약으로 명문화.
