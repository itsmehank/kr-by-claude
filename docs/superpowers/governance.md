# 프로젝트 governance 규약 (v2)

> 개별 이슈·체크리스트를 관통하는 일반 규약. 각 절(clause)은 **ID(원칙-절)** 로 인용한다 —
> plan·spec·이슈·메모리는 규칙을 재기술하지 않고 이 ID를 인용한다(4-5).
> 발단 사례를 각 절에 병기한다. v2 = #155 규칙 전수조사(2026-09-09, 787건 → 4원칙)의 통합.
> 절 본문의 "원천"은 그 규칙의 정식 정의가 있는 곳이다. 원천이 다른 문서면 여기서는 인용만 한다.

## 원칙 1: 제거 판정

게이트·상수·파생값을 판정에서 **제거**할 때의 판정 기준(1-1)·기록 처리(1-2)·보호 조항의 한계(1-3).

### 1-1. 제거 판정 4조건

**네 개 다 충족할 때만 지운다. 하나라도 아니면 안 지운다.**
- (a) 제약 추가형·필수 매개변수 아님 — 제거 후 파이프라인 정상.
- (b) 커버리지 손실 없음 — 같은 책 요구를 담당하는 다른 장치가 남아 있음.
- (c) book-mandated 신호와 방향 충돌.
- (d) 미정의 계산 없음 — 산출·소비 동시 제거.

발단: #151(PR #152, 2026-09-02) 전문가 확정 — spread_wide_loose. 재적용: #158(PR #159)·#153(PR #163).
원천: 본 절(구 plans/2026-09-02-issue151 §제거 판정 기준에서 승격).

### 1-2. 기록 보존 — 파생값 vs 원시 관측

- **저장 OHLC 등에서 재계산 가능한 파생값**은 판정에서 제거할 때 기록도 함께 제거할 수 있다 — 정보 손실이
  없기 때문(예: spread_ratio_vs_avg).
- **재계산 불가능한 원시 관측**(LLM 응답·reasoning, 당시 시장 상태 스냅샷 등)은 판정에서 제외하더라도
  기록은 보존한다.
- (i) "재계산 가능"은 그 파생값의 **산출 정의 원문이 문서에 보존된 경우에만** 성립한다 — 파생값 기록 제거의
  선행 조건. (ii) 1-2는 제거를 **허용**하는 규약이지 요구하는 규약이 아니다.

발단: #151 A1(2026-09-02, 정의 원문 보존 최초 적용). 원천: 본 절.

### 1-3. 의도는 책 근거를 대체하지 않는다

결정문·스펙·주석이 어떤 조건을 "의도된 설계"로 보호하고 있어도, 그 조건에 **책 인용이 없거나**(EXTENDS·시스템
설계) **다른 도메인의 책 개념을 옮겨 온 것**(오귀속)이면 보호는 성립하지 않으며 1-1 판정 대상이다.

발단: #152 spread_wide_loose(구 프롬프트 §3.1 "의도"), #159 앵커 C4(docstring "시스템 설계", 분류 행 89.9%
차단), #163 사이징 티어·배수(#80 결정문 "의도된 2층 보수"). 세 건 모두 결정문이 조건을 보호했고, 발견은
체크리스트가 아니라 다른 작업 중의 부수 관측이었다. 원천: 본 절.

## 원칙 2: 권한 분리

> 각 주체는 자기 권한 밖의 판단을 하지 않는다.
> 리포의 사실 기반 트리거는 방법론 판정보다 우선한다.
> CC는 책 해석·source tag 부여·책에 없는 임계 신설·결측 시 동작을 스스로 정하지 않고 질의한다.

### 2-1. 리포 자동 규칙이 우선

리포 규칙의 **사실 기준 트리거**(threshold-change-checklist (a): "thresholds.py 또는 소비처를 건드렸나")는
세션·외부 문서의 방법론 판정("이건 임계 변경이 아니다", "동작 중립이다")으로 우회하지 않는다. 값 변경 0인
경우는 의존성 맵의 축2 행이 "없음"으로 채워질 뿐, 맵 생략의 사유가 아니다.

발단: #151 외부 지시문 "checklist 대상 아님"(2026-09-02) vs 상수 삭제 = 사실 트리거. 구 checklist:103
"동작 중립이면 맵 생략 가능" 조항은 본 절과 충돌하여 #155에서 철회(2026-09-09). 원천: 트리거 정의 =
threshold-change-checklist (a)~(c). 본 절은 우선순위만 정한다.

### 2-2. CC가 물어봐야 하는 경우 / 알아서 해도 되는 경우

**질의가 필요한 경우 — 예시이지 목록이 아님**: 책에 없는 수치를 정해야 할 때 / 책 문구가 둘로 읽힐 때 /
저자 간 서술이 충돌할 때 / source tag를 붙여야 할 때 / 결측·null일 때 통과인지 차단인지 정해야 할 때 /
지시에 없는 조건을 추가해야 할 것 같을 때. 판단이 애매하면 질의한다. **추측으로 채우고 사후 보고하지 않는다.**

**단독 결정 가능**: 명명·배치·테스트 구조·리팩터링·로깅 형식 등 임계값과 분기 조건에 영향이 없는 범위.

발단: 항목 ① Q-1~Q-8(2026-09-07), #153 Q-1·Q-2(2026-09-08). 원천: 본 절.

### 2-3. 물어볼 때 양식

```
[Q-n]
- 결정 사항: (한 문장)
- 선택지와 동작 차이: A/B/C 각각에서 어떤 종목이 어떻게 다르게 판정되는지 구체적으로
- 확인한 코드 사실:
- CC 추정: (있으면 "추정" 라벨 필수. 없으면 "없음")
```
여러 건은 모아서 한 번에. 해당 부분만 중단하고 독립 부분은 진행 가능. 질의한 부분은 **회신 전까지 현 구현을 유지**한다.

### 2-4. 착수 게이트

이슈·plan에 "착수 금지 / 별도 지시 / 조건 도달 시에도 지시 대기"로 표기된 항목은 전문가·사용자 지시 전에
착수하지 않는다. 조건(wake trigger) 도달은 착수 자격이지 착수 지시가 아니다.

발단: 2026-09 사이클 이슈 9건·plan 9건이 같은 문장을 반복(#155 A2 D5). 원천: 본 절.

## 원칙 3: 실험 무결성

### 3-1. 재실행 비교 금지

LLM 산출물은 **1회 실행 → 저장 → 저장본으로만 판정**한다. 멱등 재개만 허용. 개별 건 1:1 재실행 비교는
무효이며, 비교는 패턴(집계) 수준으로만 한다. 서로 다른 as_of 간 연속성 기록은 본 절과 저촉하지 않는다.

발단: 2026-06-13 verdict discipline(temperature/seed 불가 실측), 2026-06-20 backtest-2024 이슈3 철회.
원천: 본 절(구 39곳 반복 — #155 A2 D1).

### 3-2. 성과 판정은 holdout 사전등록으로만

변경의 성과 효과는 현 표본으로 판정하지 않는다. P0 재수집 후 별도 holdout 사전등록에서만 평가한다.

발단: #151(n=17, 2026-09-02). 원천: 본 절(D2).

### 3-3. 관측 라벨

배포 전후 집계·부수 측정·머지 후 관측은 "관측만 — 판정 아님"으로 표기하며 판정 근거로 인용하지 않는다.
관측이 만든 가설은 3-4·3-2 경로로만 확인한다.

발단: 2026-07-22 entry-phase 탐색(같은 기간 재사용 = 과적합), 2026-09 사이클 6건. 원천: 본 절(D3).

### 3-4. 사전등록 잠금

판정 기준·정의·arm·표본은 **결과 산출 전** 문서로 고정하고, 결과를 본 뒤 변경·소급 정의·소급 재분류하지
않는다. 결과는 본문 무수정 + 부록/append. 동결 표본은 재추첨·라이브 재계산·post-hoc 추가 금지. 재도전은
별도 사전등록 + 독립 데이터에서만. production DB는 실험 중 읽기 전용, 승인 소비자 외 소비 금지.

발단: 2026-07-02 refinement prereg §7, 2026-06-30 표본 드리프트 사고. **원천: specs/2026-08-14-evidence-tier-
amendment-v2.md §불변 및 §4** — 본 절은 요약이며 상세는 그 문서를 따른다(D4·D15·D16·D20·D21).

### 3-5. book-fidelity 예외

임계·게이트 변경은 **성과 목적이면** P0·P1 판독 전 금지(#111 후속)이나, **책 정합 교정**(오귀속·책 근거 없는
조건의 제거·척도 정합)은 이 금지의 대상이 아니다. 성과 효과는 3-2에 따라서만 판정한다.
threshold-change-checklist의 "게이트 변경은 보수화만"(:108/:113/:115) 규칙은 성과 목적 변경에 적용되며,
책 정합 교정은 방향과 무관하게 허용된다 — #152·#159가 완화 방향의 전례.

발단: #152·#157·#159·#160·#163(2026-09) 다섯 건이 이 예외로 진행됐으나 예외 조항이 문서화되어 있지 않았음
(#155 C4). 원천: 본 절.

### 3-6. 해석 규율

- n<10 국면은 underpowered로 표기하고 과해석하지 않는다.
- 95% CI가 0을 포함하거나 p≥0.05이면 "미입증"으로 보고한다 — 점추정 서사 금지.
- 기각 = "채택 안 함"이지 "해롭다 입증"이 아니다.
- 단일 run·단일 종목으로 임계를 변경하지 않는다.
- LLM 사후지식 누출 가능성 — 개별 판정 단위 해석 금지, 패턴 수준만.
- 1차 기준 실패는 가드레일 통과보다 우선한다.

발단: backtest-profitability-results(2026-07-03), backtest-2024-results(2026-06-20, HD현대일렉트릭 오판 철회),
recall-audit(2026-07-13). 원천: 본 절(#155 U1 흡수).

## 원칙 4: 데이터 계약

### 4-1. authoritative 입력은 재계산하지 않는다

payload·컬럼에서 **authoritative로 선언된 값**은 LLM이 OHLCV·지표로 재계산·재판정하지 않는다. 결정 규칙과
비산술 재량만 LLM에 잔류한다(코드는 측정, 결정은 LLM). 어떤 필드가 authoritative인지의 열거는 각 프롬프트
SSOT 블록이 정한다.

발단: #22(2026-07-13) computed_gates, #44 anchor 코드 확정, #23 conditions_summary. 원천: 본 절(D8).

### 4-2. null은 보수

go_now에 필요한 게이트가 null이면 go_now 금지. 결측 트리거는 미평가(나머지로만 판정). 필드 부재는 null과
동일 취급(재계산 허용이 아님). 전 필드 null(left_censored)은 발화 금지.

발단: #22 null 규약(2026-07-13), #157 Q-8(2026-09-07). 원천: 본 절(D9).

### 4-3. 상수 계약

- B-수치로 판정된 상수는 값 변경 금지 — 변경은 별도 사전등록.
- 값이 같아도 역할이 다른 상수는 별도로 두고 결합하지 않는다.
- backtest·production 양쪽이 참조하는 플래그·상수는 단일 출처(SSOT)이며 한쪽만 바꿀 수 없다.
- 상수 SSOT·태그·승격 규칙의 원천은 CLAUDE.md §SSOT 패턴 + threshold-change-checklist(:104 비등재, :110 승격 2곳).

발단: #166(0.20 우연 일치 결합 금지), #153(TRADE_STOP 3소비처), #55(6·5 우연 일치). 원천: 본 절(D17).

### 4-4. look-ahead 0

판정 입력은 as_of 이하 데이터만 쓴다. 기준가는 T+1, 공시는 원공시 접수일 기준. 정상 방향 위반은 버그 조사 강제.

발단: #68 rcept_no 발견 A(2026-07-22), #111 T+1(2026-08-18), #114 트립와이어. 원천: 본 절(U2).

### 4-5. 인용 규약

**plan·spec·이슈·메모리는 규칙을 재기술하지 않고 본 문서의 절 ID(예: 3-1, 4-2)로 인용한다.** 새 규범 문장이
필요하면 (i) 기존 ID 인용, (ii) 없으면 governance 승격 제안(발단 사례 필수, 원칙 1~4 중 소속) 중 하나이며
기록 문서에 규칙 원문을 신설하지 않는다(threshold-change-checklist (f)). 기존 문서의 규범 문장은 소급 수정하지
않는다 — 상단 배너로 "작성 시점 기록"임을 표시한다. 신규 문서부터 적용.

발단: #155 A2 — 21그룹이 498곳에 반복(2026-09-09). 원천: 본 절.

### 4-6. 도메인 SSOT 지정

- 매매 규칙(손절·사이징·포트폴리오) = `docs/trading-rules-book-verified.md`
- 분류 규범(패턴·verdict·§6 게이트 소비) = `prompts/analyze_chart_v3.md` · `prompts/evaluate_pivot_trigger_v1.md`
- 상수·태그([PRESERVES]/[EXTENDS]/[design-judgment]/[heuristic]) = `kr_pipeline/common/thresholds.py` docstring

governance는 이들을 재기술하지 않으며, 각 문서는 본 절을 인용해 자신이 SSOT임을 상단에 명시한다.
(프롬프트 2건의 상단 선언은 #170 시점 프롬프트 diff 0 요구로 미삽입 — 다음 프롬프트 수정 시 동반 삽입, 전문가 판정 Q-2(B).)
